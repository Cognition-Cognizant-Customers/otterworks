# MongoDB Atlas per-namespace infrastructure

This configuration owns only the MongoDB objects for one migration namespace:

- a database user named `ow-tp-<ns>` with `readWrite` and `dbAdmin` on
  `ow_tp_<ns>`;
- optionally, the caller's IPv4 access-list entry, with an ownership comment
  containing `track=mongodb namespace=<ns>`.

The shared `otterworks-demo` M0 cluster and its project are data sources. No
cluster, project, pre-existing user, or pre-existing access-list entry can be
destroyed by this configuration.

The database name is deterministically `ow_tp_<ns>` because the MongoDB
runbook does not define a target database naming convention. Set
`TF_VAR_ns`, `TF_VAR_project_id`, `TF_VAR_public_key`, and
`TF_VAR_private_key` from the existing Atlas environment secrets. The
database user needs the namespace-scoped `dbAdmin` role because idempotent
validator reconciliation updates existing collections with `collMod`; it does
not receive any `AnyDatabase` or project-level roles. The database-user
password is generated by Terraform and is stored only in Terraform state; do
not commit state files. Terraform state is isolated in a
workspace named exactly after the namespace; never apply or destroy from the
`default` workspace. Atlas access-list entries are keyed by host IP, so exactly
one namespace per host may manage the entry. On this host that owner is
`demo`. The variable defaults to `false` as a fail-safe; the `demo` owner must
pass `manage_caller_access_list=true` explicitly, while every other namespace
must pass `manage_caller_access_list=false` and rely on the existing entry.

When upgrading an already-applied pre-flag `demo` workspace, migrate the
resource address before planning; this changes Terraform state only and does
not call Atlas:

```bash
terraform -chdir=infrastructure/terraform/tp-mongodb state mv \
  mongodbatlas_project_ip_access_list.caller \
  'mongodbatlas_project_ip_access_list.caller[0]'
```

Example:

```bash
NS=demo
export TF_VAR_project_id="$MONGODB_ATLAS_PROJECT_ID"
export TF_VAR_public_key="$MONGODB_ATLAS_PUBLIC_KEY"
export TF_VAR_private_key="$MONGODB_ATLAS_PRIVATE_KEY"
terraform -chdir=infrastructure/terraform/tp-mongodb init
terraform -chdir=infrastructure/terraform/tp-mongodb workspace select "$NS" ||
  terraform -chdir=infrastructure/terraform/tp-mongodb workspace new "$NS"
test "$(terraform -chdir=infrastructure/terraform/tp-mongodb workspace show)" = "$NS"
terraform -chdir=infrastructure/terraform/tp-mongodb validate
terraform -chdir=infrastructure/terraform/tp-mongodb plan \
  -var="ns=demo" -var="manage_caller_access_list=true"
# When the plan is clean, apply the same namespace explicitly:
# terraform -chdir=infrastructure/terraform/tp-mongodb apply \
#   -var="ns=demo" -var="manage_caller_access_list=true"
```

For a second namespace, use its own workspace (for example, `NS=sidekickws`);
never reuse `default` or another namespace's workspace. Apply it with the
non-owner setting:

```bash
terraform -chdir=infrastructure/terraform/tp-mongodb plan \
  -var="ns=sidekickws" -var="manage_caller_access_list=false"
# terraform -chdir=infrastructure/terraform/tp-mongodb apply \
#   -var="ns=sidekickws" -var="manage_caller_access_list=false"
```

The teardown target selects or creates the matching workspace before checking
ownership, dropping the namespace database, or running `terraform destroy`.

The Atlas preflight defaults to the shared `MONGODB_ATLAS_URI` and the
`ow_tp_preflight` database. For a namespace migration, run
`make tp-preflight PLATFORM=atlas NS=demo`; when that namespace workspace has
Terraform outputs, the Make target resolves the generated namespace-user
credentials and `ow_tp_demo` database in memory and passes them to the probe.
The password and URI are never printed, persisted, or committed. The validator
DDL and `collMod` capabilities are therefore proven with the
namespace-scoped user against `ow_tp_<ns>`, which is the credential path used
by migrations. The shared `otterworks-app` user remains intentionally
readWrite-only and is not granted `dbAdmin` or any DDL capability.
